# Ошибки, качество макета и балансы

Справочник по трём подсистемам, добавленным в версии 1.1.

---

## 1. Обработка ошибок

### Зачем

Раньше сбой в глубине пайплайна (не оплачен Selectel, отозван ключ LLM, кончилась
квота) сохранялся в задачу как «голый» `str(exc)` — часто пустой, — и понять, что
именно сломалось, было нельзя.

Теперь каждая ошибка приводится к типу `AppError` (`backend/app/core/errors.py`):

| Поле | Что это |
|------|---------|
| `code` | Стабильный машинный код, напр. `STORAGE_PAYMENT_REQUIRED` |
| `title` | Короткая фраза по-русски — что случилось |
| `hint` | Что сделать, чтобы починить |
| `detail` | Техническое описание (ключи вырезаны) |
| `provider` / `subsystem` / `stage` | Где именно сломалось |

### Где это видно

- **Пользователю** — на экране результата проверки: заголовок, подсказка, и
  «Техническая информация» под раскрывающимся блоком. В журнале проверок причина
  падения видна прямо в строке.
- **Администратору** — **Администрирование → Ошибки**: все сбои API и worker'а,
  фильтры по подсистеме/провайдеру/источнику, поиск, сводка за 24 часа.
  На дашборде показывается самая частая причина за сутки.
- **В логах контейнера** — одна строка вида
  `(worker) [LLM_QUOTA] Google Gemini: исчерпана квота | provider=gemini | stage=spelling`.

### Коды

**Хранилище (Selectel / S3)**

| Код | Когда |
|-----|-------|
| `STORAGE_PAYMENT_REQUIRED` | HTTP 402 или `PaymentRequired` — услуга приостановлена за неуплату |
| `STORAGE_FORBIDDEN` | 403 — подсказка перечисляет все три причины, включая неоплаченный счёт |
| `STORAGE_BAD_CREDENTIALS` | Неверный Access Key / Secret Key |
| `STORAGE_NOT_CONFIGURED` | Ключи вообще не заданы |
| `STORAGE_NO_BUCKET` / `STORAGE_FILE_MISSING` | Нет бакета / нет объекта |
| `STORAGE_UNREACHABLE` / `STORAGE_UNAVAILABLE` | Нет связи / 5xx у провайдера |
| `STORAGE_QUOTA` | Превышена квота хранилища |

**LLM и OCR**

| Код | Когда |
|-----|-------|
| `PROVIDER_NOT_CONFIGURED` | Для выбранного провайдера не задан ключ |
| `LLM_AUTH` | 401/403, либо 400 с «API key not valid» |
| `LLM_PAYMENT_REQUIRED` | 402 — нет средств |
| `LLM_QUOTA` / `LLM_RATE_LIMIT` | 429; различаются по телу ответа, советы разные |
| `LLM_MODEL_NOT_FOUND` | 404 — модель недоступна ключу |
| `LLM_BAD_REQUEST`, `LLM_PAYLOAD_TOO_LARGE` | 400 |
| `LLM_UNAVAILABLE`, `LLM_TIMEOUT`, `LLM_NETWORK` | 5xx / таймаут / нет сети |

**Файлы и пайплайн**

`FILE_EMPTY`, `FILE_TOO_LARGE`, `FILE_UNSUPPORTED`, `FILE_UNREADABLE`,
`MOCKUP_QUALITY_TOO_LOW`, `OCR_EMPTY`, `PIPELINE_TIMEOUT`, `PIPELINE_OOM`,
`INTERNAL_ERROR`.

### Повторы

Коды из `_NO_RETRY_CODES` (`backend/app/workers/tasks.py`) не переотправляются в
очередь: повтор не поможет, а квоту провайдера сожжёт и спрячет исходное сообщение
за тремя такими же.

### Безопасность

`redact()` вырезает из сообщений всё похожее на ключ (`api_key`, `Bearer …`,
`sk-…`, `AIza…`) **до** записи в базу и логи.

## 2. Проверка качества макета

`backend/app/services/quality_service.py`

Гейт измеряет изображение **в том виде, в котором его получит модель**: рендер в
340 dpi, обрезка белых полей, ограничение длинной стороны 2400 px — то есть ровно
то, что делает пайплайн.

### Главная метрика: `effective_px_per_mm`

Пикселей на миллиметр реального макета. Ограничена самым слабым звеном:

- **векторный PDF с текстовым слоем** — ограничен только нашим рендером;
- **скан или PDF из картинки** — ограничен разрешением вложенного изображения
  (рендерить 72-dpi скан в 340 dpi бессмысленно). Учитываются только картинки,
  занимающие ≥ 40 % площади страницы, — логотип не должен «портить» оценку;
- **JPG** — по размеру в пикселях; заявленный dpi принимается, только если он
  похож на печатный (150–1200) и даёт правдоподобный размер этикетки (20–600 мм).

### Пороги

| Метрика | «Отлично» | «Приемлемо» | Блокируется |
|---------|-----------|-------------|-------------|
| `effective_px_per_mm` | ≥ 12 (~305 dpi) | ≥ 8 (~203 dpi) | < 8 |
| Резкость | ≥ 0.120 | ≥ 0.035 | < 0.035 |
| Контраст | — | — | < 12 (пустая страница) |
| JPG без dpi, длинная сторона | ≥ 2000 px | ≥ 1200 px | < 1200 px |

**Откуда взялись числа.** `backend/scripts/calibrate_quality.py` прогнан по 19
реальным этикеткам «Алина Фарма» (все распознавались корректно) и по их
искусственно испорченным версиям:

- реальные файлы: 8.2 – 13.4 пикс/мм, резкость 0.145 – 0.429 — **проходят все 19**;
- уменьшенные копии: 1.9 – 3.9 пикс/мм — блокируются;
- размытие Gauss r4: резкость 0.004 – 0.010 — блокируется;
- пустая страница: контраст 0 — блокируется, оценка 5/100.

Порог 0.035 по резкости лежит вчетверо ниже худшего реального файла, поэтому
нормальная этикетка его не заденет.

**Что гейт НЕ ловит:** сильное JPEG-сжатие (quality ≤ 30). Артефакты сжатия
добавляют высокочастотную энергию, и метрика резкости остаётся высокой.
Ловятся низкое разрешение, размытие и пустые страницы.

### Где это видно

1. **При выборе файла** на экране «Новая проверка» — оценка приходит сразу,
   до загрузки (`POST /api/v1/uploads/quality-check`, ничего не сохраняет).
   При «недостаточном» качестве кнопка запуска остаётся выключенной.
2. **В worker'е** — повторная проверка перед OCR; отчёт пишется в
   `check_tasks.quality` и показывается на экране результата.

Пороги меняются в **Администрирование → Конфигурация пайплайна → Порог качества
макета** (пустое поле — значение по умолчанию).

### Пересчёт калибровки

```bash
cd backend
python -m scripts.calibrate_quality "<папка с этикетками>"
```

## 3. Балансы провайдеров

`backend/app/services/balance_service.py`

### Что доступно честно

| Провайдер | Источник |
|-----------|----------|
| **Selectel** | Есть API — баланс счёта, пересчёт из копеек |
| **ABBYY** | Есть API — остаток страниц/полей (не деньги) |
| **Gemini, OpenAI, Anthropic, Grok, Yandex Vision** | **API остатка не существует.** Ключ не позволяет прочитать баланс — эти провайдеры показывают расход только в своей консоли |

Для второй группы значение вводится вручную в **Администрирование → Балансы** и
показывается с пометкой «вручную» и датой ввода. Оно **никогда** не выдаётся за
живое чтение: если у провайдера есть API, показывается API-значение, а ручное
остаётся рядом как заметка.

Пересчёт в рубли — по курсам ЦБ РФ (`cbr-xml-daily.ru`, без ключа, кэш 1 час).

**Шекель (ILS) ЦБ РФ не котирует** — в его списке 54 валюты, ILS среди них нет.
Поэтому для валют, которых у ЦБ нет, рублёвая сумма считается кросс-курсом через
доллар (`open.er-api.com`, без ключа): `RUB за USD (ЦБ) / единиц за USD`. Там, где
ЦБ котирует валюту, используется именно курс ЦБ. Если кросс-курс недоступен,
сумма показывается в исходной валюте без рублёвого эквивалента — выдуманный курс
не подставляется. Источник курсов виден в поле `rates_source`.

Специалист видит на экране «Новая проверка» баланс того провайдера, который
реально настроен в пайплайне (`GET /api/v1/checks/provider-balance`).

Токен Selectel задаётся в **Администрирование → Хранилище** отдельным полем — он
нужен только для показа баланса и не участвует в загрузке файлов.

## 4. Регрессионный набор

```bash
bash scripts/predeploy.sh      # или: make predeploy
```

Прогоняет 140 backend-тестов (pytest, SQLite, без Redis/S3/ключей), 26
frontend-тестов (vitest) и продакшн-сборку фронтенда с проверкой типов.
Ненулевой код возврата — **не деплоить**. То же самое выполняется в GitHub
Actions (`.github/workflows/ci.yml`) на каждый push в `master` и каждый PR.
